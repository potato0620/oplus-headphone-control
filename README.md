当前仅验证 OPPO Enco Air2（新声版），应用名称不表示已支持其他型号。

此项目通过分析自有 OPPO Enco Air2（新声版）与安卓欢律的通信记录独立实现，为非官方实验项目。它通过经典蓝牙 RFCOMM 切换耳机内置音效，不处理 Mac 上的音频流。

## 使用

1. 按下方说明构建后，打开 `dist/o+耳机控制.app`。当前构建目标为 Apple Silicon / macOS 15.0 或更高版本。
2. 在 macOS 提示时允许蓝牙访问；保持耳机连接 Mac，断开安卓手机中的欢律控制连接。
3. 程序在只有一台匹配的已配对 Air2 时自动连接并读取当前音效；也可以点“连接并读取”。启动时不自动切换音效。
4. 在「当前耳机」下方，功能按型号能力分类排列。Air2 新声版目前显示「声音 → 内置音效」，可选择原声、脉冲低音或悠扬人声；选中状态以耳机读回为准。
5. 「刷新状态」只查询，不切换音效。底部「运行日志」默认收起，展开后可查看和复制收发记录；收起不会清除记录。

如果没有设备，先检查系统设置 → 隐私与安全性 → 蓝牙，允许 o+耳机控制，然后点“刷新设备”。本地构建没有开发者公证，若系统阻止打开，可在系统设置 → 隐私与安全性中查看允许打开的选项。

## 自行构建

需要 Xcode Command Line Tools 与 Swift 编译器，无第三方依赖。

```sh
sh build.sh
open dist/o+耳机控制.app
```

离线协议检查（不访问蓝牙）：

```sh
dist/o+耳机控制.app/Contents/MacOS/Air2Control --self-test
```

## 已确认的抓包结果

- 两份用户本地报告均包含完整 BTSnoop 文件；较早的一份是最新一份的精确前缀。
- 设备返回名称为 `OPPO Enco Air2（新声版）`。这些结论不自动适用于旧款 Air2、Air2 Pro 或其他固件。
- 安卓通过 SDP 查询 `0000079A-D102-11E1-9B23-00025B00A5A5`，返回名为 `custom spp` 的服务，捕获到 RFCOMM 通道 15。Mac 程序每次重新做 SDP 发现，不把 15 写死。
- 最新一轮录制包含两轮 `00 → 01 → 02`，用户确认对应原声、脉冲低音、悠扬人声。六次操作都收到状态为 0 的成功回复，随后的查询也读回同一模式。
- 设置命令：`0x0406`；回复：`0x8406`；负载分别是一个模式字节与一个状态字节。
- 查询命令：`0x010F`；回复：`0x810F`；查询无负载，回复包含状态字节和模式字节。
- 会话先发送 `0x0100`，等待 `0x8100` 且状态字节为 0。捕获的两个安卓会话在此后直接查询和设置，没有参考项目中那个硬编码 REGISTER 步骤。
- 帧为：`AA`、剩余帧长的无符号变长整数、两个保留零字节、LE16 命令、单字节序号、LE16 负载长度、负载。RFCOMM 的头、credit 与 FCS 由系统处理，不属于应用负载。
- 程序按命令和序号关联回复，处理流的分片与合并，单个操作超时后关闭控制通道，不把“写入成功”当作“耳机设置成功”。

## 验证边界

安卓侧抓包与用户音效切换反馈已确认。Mac 构建、离线检查及 Mac 实机验证的实际结果见 `VALIDATION.md`。尚未验证连接 iPhone 后的音效保留，未实现 iOS App，也没有证明该耳机具备可供 iOS 使用的另一条 GATT 控制通道。

仓库不包含完整错误报告、蓝牙地址、配对设备列表或原始抓包。

## 后续适配方向

- 应用统一名称为「o+耳机控制」，计划逐款适配更多 OPPO、一加、realme 耳机。
- 当前已验证型号：OPPO Enco Air2（新声版）；其他型号均未验证。
- 新型号先确认设备识别、通信通道（RFCOMM 或 BLE／GATT）、握手和指令，再按型号声明支持的功能。
- 界面已按型号能力配置生成分类、功能卡片及选项，空分类不会显示。目前只有 Air2 新声版配置；新协议、新型号和降噪等功能仍需分别实现及验证。
- 每款设备分别记录固件版本、成功回复、状态读回和用户听感反馈，不因名称相似直接套用已有指令。

### 按型号提供控制功能

| 能力 | 规划中的操作 | 当前状态 |
| --- | --- | --- |
| 内置音效 | 查询当前音效、切换预设 | Air2 新声版已验证 |
| 降噪控制 | 降噪／通透／关闭；如型号支持，再增加降噪强度或自适应模式 | 待具体型号抓包与实测 |
| 电量显示 | 左耳、右耳、充电盒电量（以设备实际提供的数据为准） | 规划，未实现 |
| 其他设置 | 手势、游戏／低延迟模式等，按型号逐项评估 | 规划，未实现 |

后续界面根据已识别型号的能力显示对应控件。缺少硬件支持或尚未验证协议的功能不提供可操作入口；不向 Air2 新声版添加降噪按钮。

## 界面与型号能力配置（0.2.0）

- `HeadphoneProfile.supported` 为已适配型号清单；每个型号提供名称匹配规则和 `HeadphoneFeature` 列表。
- 每项功能定义分类、标题、说明、选项及对应操作，界面统一渲染，不为每个型号编写单独布局。
- 分类按声音、降噪与通透、设备、操作与手势排序，仅展示非空分类；当前仅「声音」有已验证功能。
- 设备名称兼容 Air2 新声版全名和 macOS 缓存的 Enco Air2 短名；精确匹配避免把 Air2 Pro、Air2i 等型号套用为同一设备。短名只是连接候选，不能证明其他 Air2 版本已经适配。
- 更换耳机时断开旧控制通道并重建功能区；连接或读取期间禁用操作，不将按钮点击作为成功依据。
- `--ui-preview` 可在不访问蓝牙的情况下查看 Air2 功能分类，所有设备操作禁用。
